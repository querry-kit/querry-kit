# Release and ownership contract

- Exact allowlist: `@querry-kit/nest`, `@querry-kit/nuxt`, `@querry-kit/nuxt-ui`. Check both directory and packed name, candidate version, `private`, intended set and integrity. Fail if an unexpected package **or extra release-eligible manifest** is found. No bare `vX.Y.Z` tags.
- Root `.changeset/config.json`: `access: public`, no fixed/linked groups, `privatePackages.version: false`, `privatePackages.tag: false`. Archive or document the disposition of private-site entries before enabling the new queue. Keep ordinary dev links out of peer-range decisions. A truly incompatible peer change requires explicit review, range change and consumer tests.
- One version PR confined to the due libraries, corresponding changelogs and necessary lockfile/queue updates. UI-only → UI; Nest + Nuxt UI with compatible untouched Nuxt → Nest + UI; docs-only → no npm release/version tag. Package tags have form `@querry-kit/nuxt-ui@4.3.1`.
- Proposed publisher: central `.github/workflows/publish.yml`; owner must configure that exact `publish.yml` filename, repo and environment (if used). Version-PR automation is separate. Restrict npm OIDC permission to the protected publish job on a supported GitHub-hosted runner/npm CLI. Package install, tests, PR jobs and rehearsals get no publication credentials. The independent Pages deploy job uses its own narrowly scoped Pages/OIDC permissions.
- Serialize releases. From a clean checkout of the reviewed release commit, build once, inspect and install the exact tarballs, record digests, then publish **those bytes** with provenance. Do not force-add `dist`, create a new release commit, or publish whatever happens to be in the workspace.
- For each candidate, confirmed missing version permits publication; auth/network/registry errors stop. Existing expected version with matching integrity and provenance is recorded as already complete on retry; mismatch stops the entire release. Verify `latest`, integrity, provenance and package tag at the reviewed SHA; compare all non-target dist-tags with the preflight snapshot.
- Before switching each binding, old publisher off → binding changed and verified by npm owner → central permitted. Before publish, rollback in reverse order with both disabled during transfer. After partial publish, retry only missing candidates from the same reviewed SHA, never overwrite. Do not archive sources until legitimate release and Pages checks have passed.
