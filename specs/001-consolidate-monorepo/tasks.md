## Dependencies, parallel execution and delivery strategy

| Boundary | Order and parallel opportunities | Exit |
| --- | --- | --- |
| Freeze and import | T001 → T002/T003/T004 in parallel → T005–T010 in order. No concurrent Git imports. | Four independent commit sets, zero missing SHAs, four identical trees on merged `main`. |
| US1 / MVP | T010 → T011 → T012 → T013/T014/T015/T016. These four have separate file ownership; run final combined checks after all land. T017 follows all four, then T018. | One clone demonstrates a library change in both consumers. |
| US2 | T019 needs the built workspace from T012. T020/T021/T022 can run in parallel after T019; T023 can run alongside them after T016. T024 requires those results and T018. | Packed consumers and production-prefix docs pass independently. |
| US3 | T025 and T026 can run in parallel after US2, using T003's baseline. Both feed T027 → T028. | Exact release sets and recovery behavior proven without publishing. |
| Handoff | T028 → T029 → operator approval → T030 → real release and Pages proof T031 → retirement T032. | Tested cutover with observable recovery and historical access. |

**MVP:** T001–T018. Review the import alone first; the MVP is the later contributor workflow, not a release or publisher switch. Deliver US2 and US3 incrementally and keep operational evidence distinct from local checks.
