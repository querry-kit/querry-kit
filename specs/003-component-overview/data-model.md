# Catalog content model

A category has a heading, introduction and ordered cards. A card belongs to exactly one category and contains the public component name, a one-sentence purpose, an internal documentation path, an optional heading fragment and a decorative preview. The public names in the catalog must match the component registrations; each name is unique across categories. Shared guides may have multiple incoming links, but each component must land at the relevant section. No user state, storage or network request is needed to browse the catalog.
