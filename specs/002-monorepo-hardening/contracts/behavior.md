# Runtime behavior contracts

**F02 — Row identity.** Include `identityKey` (default `id`) in `fields` in addition to requested visible and static fields. Deduplicate without losing nested selections. `updateRow` matches exactly one loaded identity using the existing comparison semantics. Null/undefined keys and keys not currently loaded are no-ops; zero is valid. Keep existing return type, persisted preferences and grouping behavior. Regression: with two rows and hidden `slug`, update the second, then attempt a keyless patch; the first row never changes.

**F05 — Autocomplete errors.** Preserve the public `error` ref. Track the latest relevant failure separately for selected items and search results; expose the most recent unresolved one. A successful retry or cleared selection clears its own failure, not an unrelated one. Late results cannot change the state of a newer generation. Regression: exercise both lanes failing, one recovering and a stale rejection arriving after its successful retry.

**F06 — Distinct pagination.** For rows `(A,1), (A,1), (A,2), (B,1)`, distinct by the first field gives two groups; distinct by both gives three. At page size two, the latter has two pages, including on page 2 or on an empty out-of-range page. Apply the exact same access-scoped `where` to the total and the rows. Do not infer total from the current page. Preserve regular count behavior for absent/empty `distinct`; do not alter standalone `count()` or the response schema. Count all unique tuples before slicing and keep tie-breakers/order and item projection on the page query. Tests must include records outside the permitted scope and explicit `select`/`include`. For cursor-based calls retain the existing total-before-pagination convention.

**F07 — Persona transitions.** Apply account-owned abort signals only to resource reads; preserve caller cancellation when composing signals. A write must never be presented as rolled back merely because its response was lost. Track outstanding writes on the current client, release the counter on all settlement paths, and block a persona switch while a write is pending. Do not start account-bound writes while switching. An ambiguous network outcome prompts a scoped refresh before retry. Keep server-side authorization and cookie/origin enforcement unchanged. Regression: hold a PATCH response, attempt to switch, settle the write and switch; the new account sees only its own refreshed resources. Retain the existing held-GET test.

**F08 — Switch names.** Preserve native switch behavior, localization and existing action-text overrides. The accessible name combines the localized action and actual column header (stable ID if header text is empty). Two switches must be uniquely locatable by role and name without relying on their enclosing rows. Pressing Space on the Priority switch toggles Priority only. Verify keyboard reset/Escape still works.
