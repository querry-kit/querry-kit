# Dependency, CI, package and release contracts

**F01 — Dependency graph.** Limit the change to affected `brace-expansion` 1.x resolutions; confirm the minimum safe registry version and advisory range at implementation. The observed floor is `1.1.21`. Preserve the 24-hour age policy, lockfile ownership and unaffected major lines. A scanner alert indicates affected package presence, not demonstrated reachability by public consumers.

**F03 — Publish confirmation.** One invocation may submit a given reviewed archive at most once. After acceptance, check the registry read-only with bounded backoff (proposed budget: ten minutes; injected clock in tests). Temporary absence, delayed attestations or transient reads must not lead back to the submit path. When metadata, bytes, expected provenance and dist-tags converge, write the scoped Git tag at the reviewed SHA. A positive mismatch of digest/source or an unexpected tag stops immediately. On timeout report SHA, package/version and artifact identity so an operator can resume confirmation without rebuilding. Distinguish a fresh candidate from a previously accepted or ambiguously submitted one on rerun; do not decide to resubmit solely from temporary registry absence.

**F04/F11 — Required checks and Pages.** Preserve `Workspace checks` as the stable aggregate check for every PR, including documentation-only changes. Example-only changes exercise Workboard and its dependencies. Nuxt changes exercise dependent UI, Workboard, docs and packed consumer fixtures. Workflow, root config, lockfile and unclassified changes select all. A failed, canceled or unexpectedly skipped required job cannot pass the aggregate. Keep branch-rule administration separate from workflow deployment. Save original rules and verify effective enforcement before declaring success.

The generated Pages tree tested under `/querry-kit/` is the artifact to deploy. Record source SHA, run ID, artifact ID and digest. PRs may test but cannot promote artifacts; protect Pages/OIDC permissions at the deployment boundary. Reject incorrect source event, repository, branch, revision, expired artifact or digest mismatch. Re-run the trusted build/test pipeline if an artifact expired. Verify the live revision, deep links and package changelogs separately.

**F09/F10 — Consumer compatibility.** Retain immutable migration evidence; make routine CI read a separate maintained contract. Gate name, public visibility, scoped repository directory, license, declared entrypoints and their real targets, formats, types, supported peers, and absence of local/Git runtime dependencies. Compare semantic public surface rather than incidental chunks. A deliberate additive export needs a contract update; removing a supported entry requires the package's breaking-change policy. Keep exact tarball digests and publish only the tested bytes.

For each library, install the pack outside the workspace with normal npm peer resolution and typecheck an actual use of its public API. Keep the special absent-optional-peer fixture distinct. Preserve the UI matrix (Nuxt `0.2.10`/`1.0.0` × VueUse `14.4.0`/`15.0.0`) and add a current supported pair. Include controlled negative cases: missing entrypoint, incompatible peer range and unusable public type. Do not widen ranges or add runtime dependencies solely to silence a fixture.

**F12 — Guidance.** The central security policy identifies the supported packages and current private reporting destination. Contributor guides target central issues, PRs and package directories. Remove inactive nested jobs/configuration only after mapping each meaningful check to an active replacement. Preserve historical snapshots; update the migration status and runbook with links to #53's closure, real release, deployment and source retirements.
