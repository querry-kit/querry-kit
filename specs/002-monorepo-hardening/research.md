# Phase 0 decisions

Evidence combines the original review of `37ee387`, a read-only library design check, and a read-only delivery check. Results here are planning inputs, not claims that the changes have shipped.

| Finding | Decision | Rationale and alternative considered |
| --- | --- | --- |
| F01 | Target the affected `brace-expansion` 1.x range at `1.1.22`; reconfirm advisories at implementation and refresh the root lockfile with pnpm `11.28.9`. | `minimatch@3.1.5` permits `^1.1.7`; the current graph resolves `1.1.18`. GitHub alerts 79–81 require at least `1.1.21`; `1.1.22` was available outside the age hold. Prefer this maintenance release over a dependency-wide upgrade. The similarly named `braces` patch is unrelated. |
| F02 | Seed the projection with the configured identity plus explicit static fields; reject a nullish patch identity before looking up a row. | The current implicit `id` and `Object.is(undefined, undefined)` can replace the first row. Requiring users to add a hidden column would push a correctness invariant into every consumer. |
| F03 | Add an explicit read-only confirmation path with bounded retries, request timeouts and an elapsed-time budget. | [The first central publish](https://github.com/querry-kit/querry-kit/actions/runs/45080615845) succeeded at npm and the immediate verification read was still missing. Attempt 2 verified the original SHA and archive. Reject a fixed sleep, blind republish or rebuilding from current `main`. Make a resumed confirmation of an accepted/uncertain submission unambiguously read-only (persist submission state or an explicit confirm-only recovery mode); retain per-package recovery for independently missing candidates. |
| F04 | Require `Workspace checks` from the verified GitHub Actions app (observed app ID `15368`) on `main`, without replacing the deletion rule. | The effective rules API returned only deletion protection; the classic required-check endpoint was not configured. Requiring every matrix job would interfere with legitimate skips. First confirm the exact context on real PRs, then let an authorized operator enable and verify the rule. |
| F05 | Maintain two internal error lanes and derive/update the existing public error ref from unresolved failures. | Request generations already separate selected items from query results. A blanket error reset on any success would hide the other lane's failure. Preserve the current public surface. |
| F06 | Preserve supported distinct pagination: count the distinct scalar-key tuples with an unpaged, key-only `findMany` using the same scoped predicate. Retain the existing count fast path for absent/empty distinct. | The generic delegate already supports `findMany`; a new mandatory `groupBy` or transaction API would break adapters. Counting raw rows is wrong. The key-only fallback transfers one record per unique tuple, so document and measure this cost; consider an optional delegate-level optimized count later if justified. Never silently truncate totals. Separate reads do not promise snapshot isolation. |
| F07 | Scope cancellation to resource GETs, compose account and caller signals, and coordinate mutations with persona switches at the shared client/session boundary. | The current interceptor checks URL but not method and replaces `config.signal`. Merely canceling a client request cannot undo a committed server write; disabling a single form button would leave other mutation paths exposed to the same race. |
| F08 | Give the native switch a localized accessible name containing its column header, falling back to its ID. | Current switches share one label. Use the existing i18n surface rather than a new widget or an English-only concatenation that breaks locale-specific wording. |
| F09 | Establish a maintained package-contract source separate from migration evidence, with an optional historical replay. | Exact old dependency maps and filenames conflate compatibility with one past build. Validate reviewed exports, metadata and distributable contents; allow incidental chunk renames only under an explicit file policy. Keep target existence, portability and candidate-byte checks fail-closed. |
| F10 | Add genuinely peer-enforced external consumers with used API types; keep minimal optional-peer and supported matrix fixtures. | `--legacy-peer-deps` and unused type imports can conceal integration failures. Use `npm install --strict-peer-deps` and strict TypeScript compilation against the installed tarball. Distinguish the headless Nuxt library from Nuxt UI's registerable module; keep a realistic application plugin for the former. |
| F11 | Promote a tested Pages artifact from a trusted `main` push after aggregate success; implement a small tested path selector instead of introducing a build orchestrator. | Today docs are rebuilt after testing. Prefer upload and promotion in the same workflow run, with a separate privileged deploy job, over copying artifacts from arbitrary runs. Retain conservative selection on manual events, unknown paths and invalid diffs. Consider old and new paths on renames; any library changelog affects docs. |
| F12 | Map obsolete metadata to its active replacement before deletion; make security reporting, contribution links and #53 execution status authoritative centrally. | The 15 package workflows plus the example workflow are inactive at nested paths. The example workflow still references a removed staging script. Review obsolete patch references separately from active package-local tooling. Do not remove config just because it is nested. Preserve historical README redirects and frozen evidence. |

No unresolved design question blocks planning. Operational confirmations (new alert disposition, ruleset approval, live artifact identity) are intentionally future acceptance checks.
